# Plan a declarative workflow

Author an `ai-sdlc-workflow/v2` TOON document. Give every node a stable ID, an
installed skill, one canonical phase entrypoint, dependencies, optional
role/action routing evidence, an optional bounded condition, and an approval
owner where required. The planner derives operations, capabilities,
side-effects, gates, outputs, and recovery behavior from the selected skill
graphs; the workflow cannot override them.

Run from an installed consumer repository. Create `workflows/release.toon`
from the schema and contract under
`.agents/skills/ai-sdlc-workflow/references/`, and create
`workflow-context.toon` containing only the predicate fields used by that
workflow. Neither placeholder file is generated by the commands below.

```bash
python3 .agents/skills/ai-sdlc-workflow/scripts/workflow.py . \
  --workflow workflows/release.toon --validate

python3 .agents/skills/ai-sdlc-workflow/scripts/workflow.py . \
  --workflow workflows/release.toon --plan \
  --context workflow-context.toon \
  --concurrency 4 --approved-node release --write
```

The planner writes `workflow-plan.toon`, the embedded `run-plan.toon`, and a
human `plan.md` under `_ai_sdlc/workflows/<workflow-id>/`. It never executes
skill steps or grants approvals. An approval-owned node is eligible only when
its ID is passed with `--approved-node`. Independent eligible nodes may share a
deterministic display wave up to `--concurrency`; the emitted runtime graph
still preserves every dependency and is safe for sequential execution.

Treat `executable: false` as a hard planning blocker. At least one condition,
approval, skill graph, entrypoint, or dependency could not be resolved from
explicit input.
Validation success is a zero exit. Planning success writes reviewed projections
below `_ai_sdlc/workflows/<workflow-id>/`; invalid dependencies, undeclared
skills, unsupported entrypoints, unapproved nodes, or unevaluable conditions
must be fixed in source input.

The planner does not execute a post-specification lifecycle. For readiness,
implementation, validation, review, and commit, use [Continue after a
specification](after-specification.md). Host execution must still negotiate each
compiled StepCard and respect its side-effect and approval boundaries.
